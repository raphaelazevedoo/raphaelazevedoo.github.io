01 · Context

Scattered information, one catalog to organize.

Game recompilation and port projects distribute documentation, releases and limitations across different repositories. The bot catalog needed a public interface to help visitors find titles and compare related projects.

The operational challenge was to incorporate new records, consult sources and update thousands of pages without uploading files manually after every change.

02 · Solution

A bilingual library, from title to source.

AllRecomps brings together over 950 projects with search, combined filters, pagination and light and dark themes. Title pages group related implementations while retaining individual pages with documentation, installation steps, requirements and limitations where available.

The website uses Astro and TypeScript, in English and Brazilian Portuguese. Python and Node.js scripts import the bot JSON files, consult GitHub, process images and prepare data for the static build.

03 · Architecture

Collect, validate, generate and publish.

  1. Import the catalogRead Recomps and Ports JSON files and identify new or changed records.
  2. Enrich from sourcesConsult READMEs, releases and images, using caching and queues to respect access limits.
  3. Validate and generateCheck data and build output before generating pages, metadata and the sitemap.
  4. Publish and verifyUpload to Hostinger, retain the previous version and compare publicly served files against the prepared package.
  5. Schedule operationsDaily synchronization with systemd after the bot update, with execution logs.

04 · Technical decisions

Traceable automation and recovery.

Review before indexing

New projects are flagged as pending, with noindex and excluded from the sitemap until review. An available release is not treated as proof of stability or full playability.

Consistent filtering across forks

Combined filters must match the same project. This prevents results that combine one fork’s platform with another fork’s technique.

Verify the content served by the host

An update revealed that the host was serving the old sitemap. Hash verification detected the mismatch and the publisher restored the previous version. The package had used a fixed modification date in 1970; the fix uses the actual preparation date, with a test for same-size updates.

Preserve the catalog during enrichment

The routine records pending issues and preserves existing copy. Invalid optional fields are flagged for review; importing does not require changing the bot files.

05 · Results

Published catalog and an operational daily routine.

Synchronization was installed on the Linux server and its execution completed successfully. The October 13, 2026 update incorporated 4 new projects and 6 updated records, reaching 954 projects with 22 pending review.

That build generated 3,638 HTML pages and 3,568 eligible sitemap URLs. The routine now runs daily at 09:30 Brasília time, following the bot update at 09:00.

The project combines data integration, batch processing, static generation, validation and failure recovery. The public interface makes the catalog searchable while automation supports its ongoing updates.

Build metrics and operation recorded on October 13, 2026; catalog counts change over time. Editorial verification does not replace testing the games. Traffic, Google rankings and performance gains have not been measured. Developed with AI assistance.
